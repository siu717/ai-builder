# 5분 데모 스크립트

[PRD](../PRD.md) 12장의 1~6단계를 그대로 따라가는 시연 순서입니다. 버튼 이름은 화면에 보이는 글자 그대로 적었습니다.

API 키가 없어도 끝까지 시연할 수 있습니다. 그 경우 **샘플 분석**과 **샘플 컨설팅** 버튼만 사용합니다.

## 시작 전 준비 (발표 10분 전)

| 확인할 것 | 방법 | 정상 상태 |
|---|---|---|
| 서버와 알림 워커 | 터미널에서 `npm run dev` | `[web] ✓ Ready`와 `[reminders] 캠퍼스 비서 알림 워커 실행 중 (5초 간격)`이 모두 보임 |
| 접속 | Chrome에서 `http://127.0.0.1:3000` | **오늘의 캠퍼스** 화면 |
| 워커 연결 | **설정** 화면 맨 아래 | `예약 알림 서버` 옆에 **실행 중** (`연결 대기`면 워커가 꺼진 것) |
| 브라우저 알림 | **설정 → 브라우저 알림 → 알림 권한 요청 → 허용**, 이어서 **테스트 알림 보내기** | 화면 오른쪽 아래에 Windows 알림이 뜸 |
| Windows 알림 | 작업 표시줄 알림 센터에서 방해 금지 끄기 | 테스트 알림이 보임 |
| 창 크기 | 브라우저 창을 넓게 (리허설은 가로 1440px) | 왼쪽에 메뉴가 세로로 보임 |
| 이전 리허설 데이터 | 남은 일정은 **캘린더 → 마감순**에서 열어 **일정 삭제** | 일정 0개 (전체 초기화는 [런북](RUNBOOK-LOCAL.md#데이터-초기화와-백업)) |

브라우저 알림을 허용하지 않아도 시연은 됩니다. 그때는 화면 아래의 앱 내 알림만 보여 줍니다.

## 진행 순서

알림은 **3단계에서 1분 뒤로 예약**하고, 4단계를 진행하는 동안 기다렸다가 5단계에서 받습니다. 이 순서를 바꾸면 1분을 말로 채워야 합니다.

### 1단계 · 프로필과 맞춤 추천 (0:00~0:50)

1. 왼쪽 메뉴 **설정** → **학생 프로필**에 입력합니다.
   - 이름 `김국민`, 학년 `3학년`, 전공 `컴퓨터공학`, 학점 `3.8` / 만점 `4.5`
   - 관심 직무 `프론트엔드 개발`, 경력 · 보유 역량 `JavaScript, React 팀 프로젝트, Git 협업`
2. **프로필 저장** → "학생 프로필을 저장했습니다."
3. 왼쪽 메뉴 **장학금** → 카드마다 `충족` / `확인 필요`가 표시됩니다.
4. **소프트웨어 인재 장학금** 카드를 누릅니다. 오른쪽에서 다음을 짚어 줍니다.
   - **지원 조건**: `필수: 컴퓨터·소프트웨어 관련 전공` 충족, `필수: 학점 3.5 / 4.5 이상` 충족, 각각 공고 근거 문장
   - **준비할 서류**, **공고 원문**
5. **기회균형 장학금** 카드는 `확인 필요`입니다. 소득 조건처럼 프로필에 없는 정보는 추측하지 않는다는 점을 말합니다.

시간이 빠듯하면 프로필은 미리 저장해 두고 3번부터 시작합니다.

### 2단계 · 취업 컨설팅 (0:50~1:40)

1. 왼쪽 메뉴 **취업 정보** → **프론트엔드 인턴** 카드 → 아래의 **취업 컨설팅** 버튼. 목표 채용 공고 칸이 그 공고로 채워집니다.
2. **샘플 컨설팅**을 누릅니다. (API 키가 있으면 자기소개서를 붙여 넣고 **컨설팅 받기**)
3. 결과에서 세 가지를 보여 줍니다: **서류 피드백**(자기소개서 문장을 그대로 인용), **예상 면접 질문**, **준비할 일**.
4. 입력에 없는 수치나 경력은 만들지 않는다는 문구를 짚습니다.

### 3단계 · 과제 공지에서 마감 추출 (1:40~2:30)

1. 화면 오른쪽 위 **공지 입력** → **샘플 분석**. (API 키가 있으면 실제 공지를 붙여 넣고 작성일·수업 시작 시각을 넣은 뒤 **분석**)
2. 결과 확인: 마감 날짜와 마감 시각이 채워지고, **확인할 정보**에 "수업 시작 시각을 마감 후보로 사용했습니다"가 나옵니다.
   - 샘플은 작성일을 오늘로 넣습니다. 10월 3일에 실행하면 "다음 주 목요일 수업 전"이 `2026-10-08` `09:00`으로 나옵니다.
3. **확인 · 일정 등록** → **새 일정** 창이 열립니다. 제목·날짜·시각을 고칠 수 있다는 점을 보여 줍니다.
4. **알림** 영역에서 **1분 뒤**를 누릅니다. `알림 1 시각`이 지금으로부터 1분 뒤로 채워집니다.
5. **일정 저장**. 여기서부터 1분이 흐릅니다.

### 4단계 · 하나의 캘린더에 모으기 (2:30~3:30)

1. **장학금** → 소프트웨어 인재 장학금 → **신청 일정 등록** → **일정 저장**. 제출 서류가 **준비물 체크리스트**로 들어온 것을 보여 줍니다.
2. **취업 정보** → 프론트엔드 인턴 → **신청 일정 등록** → **일정 저장**.
3. **취업 컨설팅** → **준비 계획 한 번에 등록** → 날짜를 직접 고른 뒤 **일정 저장**. AI가 제안한 계획의 날짜는 사용자가 정한다는 점을 말합니다.
4. **캘린더** → **마감순**. 과제·취업 준비·채용 지원·장학금 네 종류가 한 목록에 있습니다. **월간**으로 바꿔 달력도 보여 줍니다.

### 5단계 · 알림 수신과 완료 처리 (3:30~4:20)

1. 3단계에서 저장한 지 약 1분 뒤 화면 아래에 **일정 알림: (과제 제목)** 이 뜹니다. 브라우저 알림을 허용했다면 Windows 알림 `참십 Campus · 과제`도 함께 뜹니다.
   - 워커가 5초마다, 화면이 5초마다 확인하므로 예약 시각보다 최대 10초쯤 늦을 수 있습니다. 리허설에서는 저장 후 66초에 떴습니다.
2. 왼쪽 메뉴 **알림** → **받은 알림**에 `앱 알림 발송됨`으로 기록되어 있습니다.
3. **캘린더** → **마감순** → 과제 왼쪽의 체크 상자(**완료 처리**)를 누릅니다.

### 6단계 · 새로고침 후 유지 (4:20~5:00)

1. `F5`로 새로고침합니다.
2. 일정 네 개와 완료 상태, 프로필이 그대로입니다.
3. 조금 기다려도 같은 알림이 다시 뜨지 않습니다. **알림**에는 발송 기록이 한 건만 있습니다.

## 국민대 학사일정 · eCampus 과제 가져오기 (확인 후 시연)

이 부분은 지금 만들고 있는 기능입니다. **시연 직전에 아래 순서를 직접 한 번 해 보고**, 되는 것만 4단계 뒤에 30초 정도로 넣습니다. 자세한 설명은 [KOOKMIN.md](KOOKMIN.md)에 있습니다.

| 항목 | 순서 | 상태 |
|---|---|---|
| 학사일정 | 왼쪽 메뉴 **국민대** → **학사일정** 탭 → 일정 옆 체크 상자 선택 → `앱 알림 (오전 9시)`에서 D-3 / D-1 / 당일 선택 → **선택 항목 캘린더에 가져오기 (N)** | 확인 후 시연. 10월 3일 13:35에 목록이 학교 사이트에서 불러와지는 것까지 봤고, 가져오기 버튼은 누르지 않았습니다 |
| eCampus 과제 (달력 주소) | **국민대** → **eCampus 과제** 탭 → **달력 주소로 가져오기**에 eCampus 달력 내보내기 주소(ICS URL) 붙여 넣기 → 미리보기에서 과제 선택 → 가져오기 | 확인 후 시연. 실제 계정의 주소가 필요합니다 |
| eCampus 과제 (북마클릿) | 같은 탭 **북마클릿으로 가져오기** → 버튼을 북마크바로 끌어다 놓기 → eCampus에 로그인한 화면에서 북마크 클릭 | 확인 후 시연. 실제 eCampus 화면에서 실행해 본 적이 없습니다 |

주의할 점:

- 달력 주소에는 본인 인증 토큰이 들어 있습니다. 화면을 공유한 상태에서 주소를 그대로 보여 주지 않습니다.
- 학교 사이트가 느리거나 응답하지 않으면 이 부분은 건너뜁니다. 나머지 시연은 학교 사이트와 무관합니다.

## 막혔을 때

| 상황 | 화면에서 보이는 것 | 대응 |
|---|---|---|
| API 키가 없음 | 공지 입력·취업 컨설팅에 `AI 연결 대기`, **분석**·**컨설팅 받기**를 누르면 "ANTHROPIC_API_KEY를 설정해 주세요" | **샘플 분석**, **샘플 컨설팅**으로 진행합니다. 샘플 결과에는 `샘플` 표시가 붙습니다 |
| 워커가 꺼짐 | 1분이 지나도 알림이 안 뜸. **알림 → 예약된 알림**에 계속 남아 있음. 설정 맨 아래 `연결 대기` | 터미널을 확인하고 `npm run dev`를 다시 실행합니다. 켜지면 5~10초 안에 밀린 알림이 발송됩니다 |
| 브라우저 알림 권한 거부 | Windows 알림이 안 뜸 | 화면 아래 앱 내 알림과 **알림** 목록으로 보여 줍니다. 앱 내 알림은 권한과 무관합니다 |
| 일정 저장이 403 | "같은 앱에서 보낸 요청만 허용됩니다." | 주소창이 `http://127.0.0.1:3000`인지 확인합니다. [런북](RUNBOOK-LOCAL.md#403-같은-앱에서-보낸-요청만-허용됩니다) |
| "1분 뒤" 저장이 거절됨 | "알림은 마감 날짜 또는 시각 이전으로 설정해 주세요." | 마감이 1분 안쪽인 일정입니다. 날짜가 내일 이후인 일정에서 누릅니다 |
| 화면이 비어 있음 | 일정 0개 | **오늘** 화면의 **샘플 일정 추가**를 누르면 네 종류 일정이 한 번에 들어옵니다(일정이 하나도 없을 때만 보이는 버튼) |
| 서버가 안 뜸 | 터미널 오류 | [런북의 문제 해결](RUNBOOK-LOCAL.md#문제-해결) |

## 리허설 기록

2026-10-03, Windows 11 · Node 24.15 · Chrome에서 1~6단계를 자동화 스크립트로 처음부터 끝까지 한 번 실행했습니다. API 키 없이 샘플로 진행했고, `main`을 병합하기 전의 `feat/hansiwoo/mvp` 기준입니다.

- 네 종류 일정이 한 캘린더에 등록됨
- 1분 뒤 알림: 저장 후 66.1초에 앱 내 알림, 브라우저 알림 1건(`참십 Campus · 과제`)
- 완료 처리 후 새로고침: 일정 4개와 프로필 유지, 알림 재발송 없음, 발송 기록 1건

사람이 직접 클릭하는 리허설과 실제 API 키를 쓴 분석, 텔레그램 발송은 이 기록에 포함되지 않습니다.
